# SantientPHP v0.2.1 Release Notes

**Release Codename:** Compiler Reliability & Runtime Hardening  
**Release Type:** Stabilization and Engineering Improvement Release  
**Release Date:** November 2026

---

## 1. Executive Summary

SantientPHP v0.2.1 establishes unprecedented compiler correctness, runtime reliability, and cross-platform determinism. Building upon the architectural foundation introduced in v0.2.0, version 0.2.1 prioritizes engineering rigor: **correctness before optimization, reliability before features, and measurable stability across every compiler stage**.

---

## 2. Key Accomplishments by Milestone

### M1: SPHIR Verification & SSA Correctness (P0)
- **Dedicated SPHIR Verifier**: Validates dominance properties, single definition rules, block terminator positioning, operand type conformance, and incoming phi edge consistency across all CFG edges.
- **Critical-Edge Splitting**: Added `CriticalEdgeSplittingPass` to identify and break critical CFG edges with intermediate trampoline blocks before register allocation.
- **Exhaustive Testing**: 418 rigorous IR verification tests validated across 200 parameterized invariant variations.

### M2: Phi Lowering & Parallel Copy Resolution (P0)
- **Parallel Copy Cycle Resolution**: Implemented topological sort copy scheduling with scratch-staged cycle breaking in `X86_64CodeGen::emitParallelPhiCopies`. Destinations undergoing cycle permutation are safely saved to scratch and redirected without value loss.
- **LSRA Hardening**: Linear scan register allocator hardened with Poletto & Sarkar furthest-next-use spilling heuristic under extreme register pressure.

### M3: ABI & Calling Convention Invariants (P0)
- **Internal Fast ABI & C ABI Parity**: Validated calling conventions across 0 to 8+ parameters, mixed scalar/floating-point values, and deep recursion.
- **16-Byte Stack Alignment**: Guaranteed strict 16-byte frame alignment at every call boundary on both Windows x64 and System V AMD64 ABIs.
- **Callee-Saved Preservation**: Robust preservation and restoration of non-volatile registers (`rbx`, `rsp`, `rbp`, `r12`, `r13`, `r14`, `r15`, and Windows x64 non-volatile `rsi`, `rdi`) across function calls and early returns.

### M4: Memory Safety & Allocation Reliability (P0)
- **Escape Analysis Hardening**: `EscapeAnalysisPass` now computes transitive alias closures across `Cast`, `GetElementPtr`, and `Phi` instructions, strictly forbidding stack demotion when pointers escape via return, memory store, thread spawn, or cyclic loop boundaries.
- **Slab Allocator Double-Free Protection**: Small allocations ($\le 64$ bytes) and large allocations (> 64 bytes) are monitored with magic canaries (`SPH_SLAB_MAGIC`, `SPH_LARGE_MAGIC`) and safe freed-pointer history tracking, eliminating use-after-free and double-free crashes.
- **Memory Debugging API**: Atomic counters tracking total allocations (`sph_alloc_count`), deallocations (`sph_free_count`), live bytes (`sph_current_bytes`), and peak memory (`sph_peak_bytes`).
- **Memory Ownership Model Specification**: Comprehensive documentation published in `docs/architecture/memory_ownership_model.md`.

### M5: Backend Differential Testing (P0)
- **Native x86_64 vs. LLVM IR Parity**: Validated identical semantics and bitwise-exact outputs across `-O0`, `-O1`, `-O2`, and `-O3` optimization levels.
- **Universal IR Conformance**: Tested across integer arithmetic, floating-point math, loops, break/continue, structs, recursion, and heap box memory.

### M6: Runtime Concurrency Hardening (P1)
- **Atomic Promise Transitions**: Promise state transitions (`SPH_PROMISE_PENDING` $\to$ `SPH_PROMISE_FULFILLED` or `SPH_PROMISE_REJECTED`) are strictly atomic via `__atomic_compare_exchange_n`, guaranteeing immunity against multi-threaded race conditions.
- **WebSocket Protocol Hardening**: Safe close handshake handling and complete null-pointer safety across WebSocket transmit and receive paths.

### M7: Cross-Platform Parity & CI Matrix (P1)
- **Dual-Platform CI Matrix**: Automated GitHub Actions workflow testing both Windows x86_64 (MinGW-w64 UCRT64) and Linux x86_64 (Ubuntu GCC).
- **Platform Matrix Documentation**: Comprehensive support matrix published in `docs/platform_matrix.md`.

### M8: Compiler Fuzzing & Property Testing (P1)
- **Property-Based Testing**: Validated that optimization passes (`ConstantFoldingPass`, `DeadCodeEliminationPass`, and the full `PassManager` pipeline) are strictly idempotent: $P(P(M)) = P(M)$.
- **Fuzz Testing**: Implemented `tools/fuzz/fuzz_lexer_parser.cpp` with zero crashes or unhandled exceptions across thousands of pseudo-random corrupted byte streams.

### M9: Diagnostics, LSP & Formatter (P2)
- **Multi-Span Error Formatting**: Support for caret underlines, secondary notes (`----`), and actionable help suggestions (`= help: ...`).
- **Formatter Idempotency**: Verified formatting idempotency over complex classes, interfaces, match expressions, and nested blocks: $\text{fmt}(\text{fmt}(C)) = \text{fmt}(C)$.
- **LSP Fault Tolerance**: Symbol outline extraction and hover providers function gracefully over malformed syntax trees.

### M10: Toolchain Release & Verification (P2)
- **Full Test Suite**: Exactly 6,627 tests pass with a **100% success rate (0 failures)**.
- **Toolchain Verification**: All 14 CLI commands (`build`, `run`, `check`, `fmt`, `doctor`, `lsp`, `bench`, etc.) verified on Windows and Linux.
